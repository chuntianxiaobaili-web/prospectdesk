# v0.4 完整功能验收

本文件用于整合后的下一轮测试；生成文件不启动真实发送。按 Edge、Chrome、Yandex 分开执行，各自记录通过、失败或未测，详见 [三浏览器流程](MULTI_BROWSER.zh-CN.md)。

## 先做整包本地验证

运行 `npm test`、`npm run check`。检查真实插件注册工具到服务、执行器、页面适配器的接线；验证账号锁、并发、关闭、截止、记录不重用、回执与清理分离。官方 Harness 环境可另外运行 verification 下的集成脚本。模拟邮件使用 .test 地址，模拟结果不计入实际发件数。

原路线回归应覆盖：研究/历史排重、学习来源门、双语稿、批准快照、版本变更撤销批准、排队、暂停、回执与草稿清理。现有草稿路线不自动补造上述记录。

## 真实浏览器完整发送链路

1. 接入本轮明确指定的浏览器与账号。核对 browserId、实际版本与固定目标，再运行邮箱只读兼容性检查；记录适配器版本与检查时间。
2. 从页面锁定本次候选原草稿并检查历史。排除对应已发记录；记录候选数、可执行数和排除原因。候选不够时按实际数量运行，不扩大范围。
3. 对本次残留原草稿的永久删除范围取得明确确认后，写入准确 ID 名单；未确认项保留。旧任务中的 26 封确认不沿用到新批次。
4. prepare 默认一次 1 小时、目标 50、固定 72 秒最短间隔，读取精确初始草稿总数。准备阶段应为 0 发送、0 删除。
5. 正式开始后保持同一实例与同一截止，按固定程序 step 串行执行；现场不同时人工编辑该标签页。观察新的发送回执、回执落盘、原草稿消失证据。
6. 出现异常保存日志；不知道是否成功的邮件不重试。界面改版时交给只读检查重新判断。恢复如有需要必须保留原截止。
7. 到点检查所有发送/删除意图的时间。截止后的核对只读，不以补清理为由继续删除。finish 读取最终草稿总数。
8. 归档当前浏览器任务并释放同账号锁后，才准备下一浏览器。各轮重新查历史，不重复已发送草稿。报告开始/截止/实际结束时间、目标、已确认发送、已确认清理、候选未发送、待清理、结果不明、邮箱最终草稿总数及来源。清理按自动消耗和人工批准永久删除分别计数。

## 通过标准

- 实际动作均落在原工作窗口内；重复 start 不重置截止。
- 只有没有对应发送记录且发送前检查通过的选定草稿被处理。
- 点击不算成功，新的精确回执才计入 sent。
- 只有已确认发送且内容未变的原草稿被清理；未确认发送保持原样。
- 发送与清理分开统计；停止/异常不触发重复发件。
- 账号变更、缺失或重名控件停止相应动作。
- 整包入口确实驱动当前连接器，未使用模拟邮箱代替真实测试。
- 如不足 50 封，给出实数与原因；只有实际完成才报告“1 小时目标 50 封通过”。

完整找客到实际发件还需验证真实研究来源、学习台账、人工批准以及在邮箱保存原文的交接。现有草稿测试仅覆盖从候选草稿到回执、清理和报告的完整链路。
