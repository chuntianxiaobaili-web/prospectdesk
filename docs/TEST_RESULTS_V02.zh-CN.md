# v0.2 本地专用浏览器版：测试记录与边界

日期：2026-10-23；开发和测试在 dot 云端 Linux 完成，未操作用户电脑、真实邮箱、客户资料或登录凭据。

## 已验证范围

本轮最终复跑：**45 项模块测试通过**；另外 **9 项独立浏览器模拟驱动检查、2 项本地 HTTP/模拟驱动检查通过**，Windows 脚本文本检查通过。不同测试覆盖有重叠，不作为生产兼容性数量。


- 原工作流模块测试及新增浏览器生命周期、模拟邮箱适配器合同测试，使用合成资料和模拟浏览器驱动。
- 独立验证专用 profile 派生路径、默认 Chrome/Edge profile 拒绝、大小写和路径分隔符处理、外来 profile 与符号链接拒绝、保持 Chromium sandbox 设置。
- 同一目录的多控制器及真正的第二个 Node 进程不能取得已占用的锁；失败不能删除其他控制器的锁。意外断开后在途动作未结束时重开不能提前释放旧锁。
- 启动过程中收到关闭请求，会等待启动结束后关闭新 context，不遗留后台浏览器。无效 profile 配置在获取工作流锁之前拒绝，避免残留锁阻断重试。
- 默认启动暂停；人工接管先暂停并等待在途动作结束；关闭/重启后不自动恢复队列。意外浏览器关闭后通知队列暂停。
- 实际 loopback HTTP 服务加模拟浏览器驱动：跨 Origin、Host 欺骗、缺失动作 token 被拒绝；合成草稿精确审核入队后，暂停/接管/关闭/重启仍保留队列且不会自行发送。
- Windows 安装/启动脚本静态检查：写入目录或下载浏览器前先做只读路径验证；使用锁定依赖；不修改执行策略、不请求管理员、不杀用户浏览器、不连接已有默认 profile。

2. **Windows 尚未执行。** 当前没有 Windows/PowerShell 运行环境。脚本完成静态审查，不等于已在 Windows 真机安装、启动或图形界面验收。
3. **当前邮箱适配器只针对内置模拟页面。** 仅接受 `.test` 合成地址，不发送互联网邮件；不是 Zoho、Gmail、Outlook 或任意邮箱已兼容的证明。模拟 DOM 合同测试不是完整真实浏览器端到端测试。
4. **新增本地浏览器工具未在本轮重新完成官方 Harness 运行时全套验收。** `TEST_RESULTS.zh-CN.md` 中官方 Harness/26 个工具结果属于此前 v0.1；不要当成 v0.2 新增浏览器能力已通过真实环境验收。
5. 未调用付费模型、未发送客户邮件、未读取真实 100 篇学习资料。合成学习测试记录不增加真实学习进度。

## 独立检查复现

```sh
npm test
node verification/local-browser-qa.mjs
node verification/local-app-qa.mjs
node verification/windows-script-qa.mjs
```

前两个可选脚本使用模拟浏览器 driver；其中本地服务检查仅绑定 127.0.0.1。最后一个只检查 PowerShell 文本，不执行 Windows 脚本。测试状态放入临时目录并清理。
