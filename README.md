# 客拓工作台 ProspectDesk
### 跨行业客户研究、双语开发信与浏览器邮件执行

**当前版本 v0.6.3 · MIT 许可证**

0.6.3 修复 Codex 与 Zoho 的富文本草稿、启动锁恢复、原稿保留和扫描覆盖，并加入 WorkBuddy 只读接入。[更新与验收说明](docs/RELEASE_V063.zh-CN.md) · [客户端与云电脑兼容性](docs/CLIENT_COMPATIBILITY.zh-CN.md) · [Codex](codex/README.md) · [WorkBuddy](workbuddy/README.md)

客拓工作台把客户研究、历史排重、逐客写信、人工审核、浏览器发送、回执核对和原草稿清理串成一条有记录的工作流程。你提供行业、产品或服务资料、目标市场和工作目标，AI负责研究与文案，固定程序负责执行已经批准的邮件。

当前完整流程以企业客户的首封开发信为主。实体商品、数字产品和B2B服务的研究方向与写稿角度按输入适配；价格、库存、交期、认证和服务承诺均以真实资料为依据。

## 1. 一次任务怎样完成

1. **读懂业务资料**：读取卖方产品或服务、规格、可履行承诺、目标地区与客户类型。
2. **研究并核对客户**：由运行宿主的搜索、浏览器和文件工具采集实际证据，记录官网、公开业务邮箱、业务匹配点及来源。
3. **检查完整历史**：按公司、域名、集团、邮箱及既有筛查记录排重，保留被排除的客户与原因。
4. **逐家撰写开发信**：从一个可核实的客户事实切入，输出英文客户稿和中文审阅稿，单列推荐依据与未知项。
5. **审核精确版本**：人工确认收件人、主题及全文。改稿会使旧批准失效。
6. **保存并读回原草稿**：通过浏览器保存，重新读取准确草稿编号与全文，绑定批准版本。
7. **执行发送与核验**：固定程序串行发送；逐封核对新的已发送记录，再核对相应原稿的移除。
8. **交付结果**：输出客户表、双语稿、发送记录、清理状态与剩余数量。状态不明的邮件留待核对，避免重复发送。

**职责分工**：AI负责研究、判断与写稿；固定程序负责排程和邮件操作；检验代理检查界面与程序是否仍适用；用户确认实际要发送的版本。网页研究依赖宿主提供的工具，插件中的研究指令或证据导入本身不等于已经执行搜索。

## 2. 当前功能与运行规则

| 能力 | 当前实现 |
|---|---|
| 客户表与证据 | CSV / XLSX导入、证据字段、历史排重、研究记录导出 |
| 写信方法 | 独立的首封写稿与跨行业写作指南；英文稿、中文审阅稿和逐封审核 |
| 写稿依据 | 可选产品证据加逐封审核；上游明确启用时使用100来源学习手册路线 |
| 浏览器连接 | Edge、Google Chrome、Yandex分别接入并记录身份 |
| 邮箱页面 | 中文企业邮箱与中文Gmail分别适配，浏览器品牌和邮箱页面分别检查 |
| 精确执行 | 账号、收件人、主题、全文、原草稿编号与版本绑定；单账号串行与日志记录 |
| 发送节奏 | 固定最短间隔；原获批包队列另支持显式批次暂停。本轮浏览器试验设为72秒 |
| 工作时长 | 按用户输入设置，如1小时或5小时；省略时长不设时间截止 |
| 长时提醒 | 连续运行8小时提醒一次并继续；需要宿主实际显示或活跃代理显示后确认 |
| 原稿处理 | 新回执核实后再处理准确原稿；邮箱自动消耗时完整核对缺失；永久删除按本次具体授权执行 |
| 异常恢复 | 未知发送先只读核对；已发邮件清理失败保留已发事实，恢复时保持原运行窗口 |

不设时间截止时，数量目标、已批准队列、用户暂停和异常状态仍各自生效；达到目标或队列耗尽会结束本批。当前发送会话需要活跃宿主持续执行，进程退出不会自行继续旧任务。

本版排程采用明确间隔和批次配置；随机发送时间与随机数量池尚未交付。8小时提醒已经过程序时钟测试，本轮未进行连续8小时现场运行。

**开始使用前准备四类信息**：行业与产品/服务资料、目标地区与客户类型、完整客户历史、此次数量与可选时长。实际邮件先完成收件人与全文审核，再进入浏览器执行。

## 3. 我们实际验证了什么

**实发日期：2026年11月18日。两种浏览器分开测试，均通过实际邮箱页面执行，没有调用邮箱发送API。**

| 试验项 | Edge 企业邮箱 | Chrome Gmail |
|---|---:|---:|
| 本轮目标 | 10封 | 10封 |
| 真实发送并核对新回执 | 10封 | 10封 |
| 确认移除原草稿 | 10个 | 10个 |
| 本轮待发 / 待清理 / 未知 | 0 / 0 / 0 | 0 / 0 / 0 |
| 邮箱草稿总数 | 529 → 519 | 10 → 0 |

共核对**20个不同的新消息编号**；每个原稿只有一次发送意图和一次发送确认，未重复发送。Gmail的10个原稿由邮箱自动消耗，程序核对完整草稿列表中的准确编号已不存在；企业邮箱按本轮授权处理已确认发送的残稿。已发送记录证明邮箱接受了提交，不代表客户已阅读。

Gmail试验还覆盖了澳大利亚B端客户研究、历史排除、客户表、逐客双语稿、用户批准及草稿交接。14条研究记录保留10家入选和4家历史排除；4家排除项未发送。验收过程中修正了页面等待、地址展开、精确换行、可见正文结构、草稿查询和回执格式，并在原运行中核对恢复。

**工程验证：619 / 619项程序测试通过，0失败、0跳过。** 冻结程序另通过34项语法检查、5个技能格式检查和14个导出模块检查。工程测试使用合成数据，真实发送按上表另行计数。
